# Dependency Open Items — INV_SMALL_CASH migration

This register lists every dependency that the legacy Form `05_Complex/Inv_Small_Cash.xml` or the three ingested packages `BIL_INVOICE_ENGINE`, `BIL_INVOICE_API` and `BIL_IMPORT` reference and that the ingestion lacks. No such dependency is stubbed with assumed behaviour. Ids match `Billing.Invoicing.Domain.Model.OpenItemIds` (`OI-01` … `OI-58`). Locators take the form `[file:line]`. Decision ids (`D-xx`) refer to `docs/decision-log.md`, which holds the rationale. No Oracle instance exists in this run: every statement below about package runtime behaviour, binding behaviour or SQL results is UNVERIFIED.

## §1 Open-item register

### §1.1 Handling classes and closure codes

Every open item other than the three schema groups belongs to exactly one handling class:

- **Inside a retained package call** (OI-01 … OI-14, OI-16, OI-19). .NET blocks nothing: the retained package call either works in the target schema or raises, and the rule's outcome is UNVERIFIED. For OI-10, OI-11 and OI-12 the create-time posting stage sits inside `CREATE_FULL_INVOICE`. The separate operator action that needs the same package is blocking, and its member is named in the row:
  - `LegacyExternalCalls.TransferStock` → `POST /api/invoices/{invNo}/stock-transfer` 501 (OI-10);
  - `BilInvoiceApiGateway.BuildPrintUrl` → `POST /api/invoices/{invNo}/documents/invoice` 501 (OI-11);
  - `LegacyExternalCalls.SendInvoiceSms` → `POST /api/invoices/{invNo}/sms` 501 (OI-12).
- **Blocking.** The operation cannot produce the legacy outcome without the dependency, and no package call stands in for it. The member named in the row throws `NotImplementedException("OI-xx: …")`, and the endpoint returns 501 with `type: open-item`, `openItemId` and `message`.
- **Advisory.** The dependency affects only a displayed value, a non-blocking warning, or a stored value whose difference from the Form the decision log declares (OI-21, D-52). The operation proceeds and lists the id in the response's `openItems`. OI-20 is the one pre-commit check handled this way, the logged exception D-45.
- **Not built** (OI-17, OI-18, OI-25, OI-27 … OI-30, OI-34 … OI-39, OI-43, OI-50 … OI-55, OI-57, OI-58). These rows are not implemented, not built, out of scope, not invoked, never reached or not migrated. No built endpoint offers the functionality they concern, so neither blocking nor advisory applies. This is consistent with the constructs the migration does not carry and with the gap policy D-16.
- **Schema groups** (OI-15, OI-40, OI-41). Each table, view and sequence is its own item in §1.3, with its own handling: Direct query, Inside a retained package call, or Not used (D-57).

Closure codes:

- **HIS** — only the target HIS schema can close it.
- **P2** — only a phase 2 ingestion can close it.
- **Decision** — a product owner's decision closes it.

An operation whose response carries an open item never claims full parity with the Form (D-16).

### §1.3 Schema object register

The user lists all schema DDL as missing. Each table, view and sequence that the Form or the three packages reference is one item below, placed in the group of its strongest target use. An object that .NET queries sits in OI-15 even when a package also uses it, so each object appears once. `DUAL`, `SYSDATE` and `UTL_URL` are Oracle-supplied and not listed (D-57). The objects are cited by name only.

- **Direct query** (OI-15.xx). The Data member named in the row runs SQL copied from the cited Form construct. Column names come from the Form; their types and sizes follow the Form item definitions and are UNVERIFIED. A missing object or column fails with ORA-00942 or ORA-00904, which maps to 500 `oracle-error`, and no default is substituted.
- **Inside a retained package call** (OI-40.xx, and the package use noted on OI-15 rows). .NET never names the object: the package compiles and runs against it or raises, UNVERIFIED.
- **Not used** (OI-41.xx). Only a Form construct that the target does not execute reads or writes the object. The row names the open item or mapping that governs that construct; the object's DDL alone does not bring the construct into scope.

Every object closes with the target HIS schema.
